# Gate 账户看板

通过 Gate APIv4 读取自己的账户数据，算出每日盈亏、手续费构成和历史表现。
支持多个 API key（多个账户/子账户），既能看**组合聚合**，也能逐个账户下钻。
现货 / U 本位合约 / 统一账户各有各的视图，手动点「同步」刷新。

## 为什么有个后端

Gate 的私有接口要用 API secret 做 HMAC-SHA512 签名。把签名放在浏览器里等于把密钥
公开发布——任何人打开开发者工具就能拿走，而且 Gate 的 REST 也不给浏览器放 CORS。
所以形态是「一个很薄的 FastAPI + 前端只跟自己的后端讲话」，secret 从不离开你的机器。

配 key 的时候：**只勾只读权限**（不要交易、不要提现），并绑定 IP 白名单。

## 跑起来

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r backend/requirements.txt
```

```bash
cp .env.example .env
```

填好 `.env` 里的 `GATE_API_KEY` / `GATE_API_SECRET`，然后开两个终端：

```bash
./.venv/bin/uvicorn backend.app.main:app --reload --port 8000
```

```bash
pnpm --dir frontend install && pnpm --dir frontend dev
```

打开 http://localhost:5173 。前端的 `/api` 会代理到 8000 端口。

想单进程部署就先 `pnpm --dir frontend build`，FastAPI 会自动托管 `frontend/dist`。

### 多个账户

**推荐：页面右上角「账户管理」**。填 id、显示名、key、secret，勾选账户类型，点「验证并添加」——
后端会拿这对密钥实际调一次 Gate 做只读验证，通过了才保存，所以填错当场就会看到 Gate 的报错，
而不是保存之后满屏红条。添加后**先点一次「同步」**：拉取它的历史、记录今天的权益快照，
组合聚合才会把它算进去。

密钥保存在本机 `profiles.toml`（已 gitignore），重启不丢。删除账户也一样在面板里完成；
删掉后它的本地历史保留着，用同一个 id 重新添加可以接回来。

也可以手工维护：复制 `profiles.example.toml` 成 `profiles.toml`，一个 `[[profile]]` 一套密钥：

```toml
[[profile]]
id = "main"
label = "主账户"
key = "..."
secret = "..."
accounts = ["spot", "futures_usdt"]
```

注意面板和手工编辑各管一头：面板保存时会**重写整个文件**（注释会丢），手工改完要重启后端才生效。

`id` 会出现在 URL 里、也会存进本地库，**改名等于把那个账户的历史孤立掉**，所以取个短而稳定的
（字母、数字、横线、下划线）。

`profiles.toml` 存在时 `.env` 里的 `GATE_API_KEY` 就不再被读取。只有一个账户的话不用建这个文件，
`.env` 里的单个 key 会被当成一个叫 `default` 的 profile——第一次在面板里加账户时，
它会被一起写进 `profiles.toml`（密钥从环境变量挪到文件里，都在本机且 gitignored）。

每个 profile 有自己的限流器和连接池——Gate 的限流是按 key 计的，共用一个会让忙的账户拖慢闲的。

### 先看看长什么样（不需要密钥）

```bash
./.venv/bin/python -m backend.scripts.seed_demo --days 75
```

默认会给每个配置里的 profile × account 都灌一份（曲线按 profile id 生成，各不相同）。
只想灌一个：`--profile main --account futures_usdt`。

```bash
DASHBOARD_DEMO=1 ./.venv/bin/uvicorn backend.app.main:app --reload --port 8000
```

种子脚本会灌入一段网格策略形态的历史（稳定的已实现利润 + 扩大的浮亏 + 一笔入金），
`DASHBOARD_DEMO=1` 会让快照接口返回合成的持仓。演示模式下页面顶部有常驻红色警示条，
数字全是假的。

**接真实密钥之前一定要清掉演示数据**，否则假数据会和真数据混在同一个库里：

```bash
./.venv/bin/python -m backend.scripts.seed_demo --clear-all
```

`--clear` 只清当前配置里那几个 profile；如果你中途改过配置，用 `--clear-all` 才能清干净
（它会清掉所有历史，包括真同步来的，所以只在这一步用）。

## 「每日盈亏」到底指哪个

合约账户里这个词至少有四种算法，网格策略下能差出一个数量级。看板同时给两个：

| 口径 | 含义 | 怎么算 |
| --- | --- | --- |
| **权益口径** | 今天到底赚没赚钱 | 今日收盘权益 − 昨日收盘权益 − 当日净出入金 |
| **已实现净额** | 账本记了多少 | 平仓盈亏 − 手续费 ± 资金费 + 返佣 |

两者之差就是未实现盈亏的变化。**网格策略最经典的自欺场景在这里**：每一格都在成交、
已实现天天为正、页面一片红火，同时持仓浮亏在扩大、权益在往下走。所以每日盈亏图把
权益口径画成柱子、已实现画成灰线——柱子长期低于灰线就是这个信号。

「累计收益」「最大回撤」「夏普」都基于时间加权收益率序列（每天在前一日权益上复利），
所以入金不会被算成业绩。

## 聚合的四个坑

多账户加总不是简单相加。这四件事如果不处理，页面会给出看起来精确、实际错误的数字：

**1. 快照覆盖率。** 某天只有 A 同步了、B 没有，那天的 Σ权益 就缺了 B——加总出来像一次暴跌。
所以聚合只统计**当天在场的账户都报了快照**的日子。"在场"按每个账户自己的首末快照日判定：
中途新加的账户不会作废它加入之前的历史（那些日子的组合确实不含它），删掉的账户在其最后
快照日之后不再被期待，一直没同步过的账户则挡住所有日子——直到你点一次同步。
缺的日子标为不完整、不参与统计，页面上有 "有 N 天的数据不完整，已排除" 的提示，
下一个完整日会打上 `2d` 之类的跨天标记。**每天同步一次就不会出现这个问题。**

**2. 回撤和夏普不可加。** 组合回撤 ≠ 各账户回撤的平均，也不是最大值——分散化是真实的。
这些指标一律从组合自己的收益率序列重算。分账户表里每行的回撤是那个账户自己的曲线算出来的，
两者本来就该不同，页面上分开呈现。

**3. 内部划转。** 从 A 转到 B，两个账户各记一笔（−x 和 +x），聚合时自动相消。
但这**只在两条腿都配进来时成立**。如果 B 不在看板里，组合盈亏会错这笔钱的数额。

**4. 结算币种。** 币本位合约以 BTC 计价，不能和 USDT 直接相加。它会被排除在组合之外并明确列出，
不做换算——换算需要逐日的历史汇率，这个程序没有存，猜一个汇率比留一个缺口更糟。

另外：`/wallet/deposits` 拉来的出入金记在伪账户 `wallet` 下，**永远不作为聚合范围**——
同一笔钱在它落地的现货或合约账本里已经记过一次，两边都算就会把出入金翻倍、
进而污染所有由它推导的盈亏。

## 手续费统计

页面顶部「手续费」区支持**按日 / 按周 / 自定义日期段**统计每个账户的手续费总值：

- 按日 / 按周 / **按月** / 自定义起止日期；**日界可选 0 点或 8 点**（UTC+8）——8 点起算时
  早上 8 点前的记录归入上一个交易日（费用聚合直接从时间戳分桶，不受同步时
  固化的 0 点日界限制），周从周一起、按同一条日界线。
- 组合视图给总计 + 分账户两份表（各行相加恒等于总计）；单账户视图只给该账户的。
- 口径：**成本 = 手续费 + 资金费支出 + 借贷利息**，返佣单独列出、不从成本里扣
  （它是收入，不是费用减免）。周/区间的 maker 占比和实际费率都从加总的分子分母
  重算，不是日值的平均——1 笔全 maker 和 100 笔里 99 笔 maker 的周，合并后是 100/101。
- 边缘周会打上 `Nd` 标记（那周只有 N 天有数据），覆盖不全的周标 `缺Nd`。

- 返佣核对：**70%/10%/5% 手续费份额**、**当期返佣**（同账户现货账本实际到账，
  按同一条日界和周期分桶）、**预计额外返佣**（70% 应返 − 到账）。

接口：`/api/portfolio/fee_summary` 和 `/api/profiles/{id}/accounts/{account}/fee_summary`，
参数 `period=day|week|month`、`from_day`、`to_day`、`days`、`boundary=0|8`。

侧栏的「报告」按钮一键生成完整 Excel（就是 `export_report.py` 那份，
`GET /api/export/report?days=N`），现货账户还有「流水」页签看账本明细（可按类型筛选）。

合约账户的「明细」页还有**历史仓位**：逐仓平仓记录（时间、合约、方向、最大仓位、
持仓时长、平仓盈亏），按市场可筛选。持仓时长和最大仓位是 v3 结构新增的字段，
旧记录在下次同步时自动补全（upsert 对已存在行只填空缺字段）。

## 为什么要落本地库

Gate 的历史查询有硬限制：现货成交大约只能查最近 30 天且通常要指定交易对，合约流水
保留期在 3 个月上下，分页只有 offset/limit，深翻又慢又容易撞限流。

所以看板不是「每次打开就去 Gate 拉一遍」，而是**增量同步进本地 SQLite，前端只读本地库**。

这里有个不可逆的点：**每日收盘权益快照过了当天就永远补不回来了**。今天不开始存，这段
历史就是永久性丢失。所以哪怕你还没想清楚要看什么指标，也值得先让它每天跑一次同步。

如果某天没同步，那一行会打上 `Nd` 标记，提示这行的「每日」盈亏实际覆盖了好几天。

## 时区

`DASHBOARD_TZ` 决定日界线，也就决定了每日盈亏这一栏的每个数字。设成和 Gate 网页端
一致（通常是 `Asia/Shanghai`），否则你会花一晚上找不存在的 bug。

## 配置项

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `GATE_API_KEY` / `GATE_API_SECRET` | — | 只读权限，绑 IP 白名单 |
| `GATE_API_HOST` | `https://api.gateio.ws` | 需要区域节点时改 |
| `GATE_PROFILES_FILE` | `./profiles.toml` | 多账户配置。存在时 `GATE_API_KEY` 被忽略 |
| `GATE_ACCOUNTS` | `spot,futures_usdt` | 默认启用哪些产品，顺序就是标签页顺序；profile 里的 `accounts` 会覆盖它。可选 `spot` `futures_usdt` `futures_btc` `unified` |
| `GATE_SPOT_PAIRS` | 空 | 现货成交查询在多数账户上要求指定交易对。填 `BNB_USDT,BTC_USDT` 这样的列表作为兜底 |
| `DASHBOARD_TZ` | `Asia/Shanghai` | 日界线 |
| `DASHBOARD_QUOTE` | `USDT` | 计价币 |
| `DASHBOARD_DEMO` | 关 | `1` 时返回合成快照，界面会常驻警示条 |
| `DB_PATH` | `./gate_dashboard.sqlite3` | 本地历史库 |

## 配色与视觉

视觉是**现代明亮 SaaS** 风：浅灰底、白卡片、柔和投影、一个蓝色强调色（`#2563eb`），
深色是完整的第二套皮肤（右上角可切换）。换肤前所有色对都跑过校验器，
结果记在 `frontend/src/styles.css` 顶部的注释里。

盈亏默认**红涨绿跌**，跟 Gate 中文界面一致。浅色底用 `#dc2626`/`#15803d`
（ΔE 8.6 直接达标）；柱状图以零轴为基准 + 数字永远带 `+`/`−` 号，
颜色从不是唯一的信息通道。右上角可切**红蓝**配色（ΔE 19–21）给完全
不能依赖红绿的情况。

## 测试

```bash
./.venv/bin/python -m pytest backend/tests -q
```

覆盖的是每日盈亏的算术本身，以及上面那四个聚合坑：

- 已实现与权益口径的分歧、入金被正确剔除、出入金恰好抵消时收益率不被算成 0
- 首日没有前值时不编造差额、时区日界线、缺快照的跨天标记
- 未分类账本类型不被静默计入
- 聚合正确求和；覆盖不全的日子不产生盈亏；内部划转跨账户相消
- **中途加入的账户不作废之前的历史**；删掉的账户停止被期待；没同步过的账户挡住盈亏直到首次同步
- **组合回撤不等于最差账户的回撤**（用一个反相关的例子固定住）
- 两个 profile 用同一个 trade_id 不会互相覆盖
- v1 库能迁移到 v2 且行数、索引都保住，重复打开是幂等的
- 每个 profile 用自己的密钥签名，APIv4 签名串的构造

都不需要密钥。

## 页面结构

界面层基于 **Ant Design 6 + ECharts**（中文数据产品的标准栈）：侧栏导航、
KPI 统计卡、标签页、表格（列排序/筛选/分页是 antd 自带的）、日期区间选择器
都来自组件库；图表由 ECharts 渲染。深色模式走 antd 官方暗色算法。
窄屏时侧栏自动收起。

桌面端是**侧栏 + 工作区**两栏：左侧固定侧栏（品牌、账户/产品导航、时间范围、
同步按钮和最后同步时间），右侧内容区占满剩余宽度。

内容区分两层，控制纵向长度：

**常驻层**（永远可见）：KPI 带（12 列栅格，主指标占 4 列、副指标各 3 列）+ 实时状态
（合约的风险标尺/保证金、现货持仓、组合构成），8:4 不对称分栏。

**页签层**（图表 / 明细 / 手续费）：权益曲线和每日盈亏 6:6 并排，成本构成和风险
统计 6:6 并排——图表不需要 12 列宽，并排省一半纵向空间；明细页放所有表格孪生；
手续费页放周期统计。切换用滑动胶囊，「明细」里的长表格默认只列最近 30 天，
超过时出现「显示全部」。

这样一年期数据的页面高度从约 5200px 压到约 1600px，所有数据仍然一键可达。

## 目录

```
backend/app/config.py             profile 加载（TOML 多账户 / .env 单账户）
backend/app/gate_client.py        APIv4 签名 + 每 key 限流 + 两种分页 + 客户端注册表
backend/app/db.py                 SQLite schema（含 v1→v2 迁移）。权益快照是唯一补不回来的表
backend/app/services/analytics.py 按 scope 聚合、时间加权统计、成本汇总、分账户贡献
backend/app/services/portfolio.py 跨账户实时总额
backend/app/services/ledger_types.py  账本类型 → 经济含义的映射表
frontend/src/charts.tsx           手写 SVG 图表
frontend/src/tiles.tsx            KPI 带、距强平标尺
frontend/src/views.tsx            四个视图：组合 / 现货 / 合约 / 统一账户
```

数据的身份是 **(profile, account)** 这个二元组——前者是哪把密钥，后者是密钥下的哪个产品。
两者都在主键里：Gate 的成交 id 和账本 id 只在单个账户内唯一，跨账户会撞。
